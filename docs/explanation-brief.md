# 설명용 HTML/PPT·영상 제작 입력

SPEC §12의 필수 산출물을 처음부터 계획하기 위한 초안이다.
실제 구현·영상·이해도 확인을 이미 완료했다고 표시하지 않는다.
이 문서는 최종 HTML/PPT를 대신하는 제출물이 아니다.

## 최소 전달 흐름

| 화면/장면 | 반드시 설명할 내용 | 실제 근거 |
|---|---|---|
| 문제 | 조직/모듈마다 다른 규칙과 반복 피드백 | 사용자 문제 정의, SPEC §1 |
| 구조 | C-model 개발 부모와 리팩토링/Code Rule 자식 | 실제 초기 index/refs |
| 교정 | B가 boolean 예외 등을 올바른 자식에 공유 | 실제 발화·대상·저장 version |
| 다음 결과 | 같은 C 기능 요청에서 m_ready→is_ready | C0/C1 실제 코드·로드 |
| 보존 | 일반 m_frame_count와 기존 m_parameters, 기능 결과 유지 | 세 후보 비교·수치 검사 |
| 정리 | 내용은 새 version, 과거본 보존, 지침 유지 | v4/v5·실제 서브에이전트·C2 |
| 증거/한계 | 자동/전사/미검증을 분리 | README·make verify·전사 경로 |

이미지 패널은 입력/기존/후보 출력과 차이를 보여준다. 코드의 접두사 변화가 주 증거이며
이미지/시간만 보여주고 무엇이 다음 사용자에게 전달됐는지 설명을 빼지 않는다.
수치 배율은 실측으로만 채운다. 제품용 웹 UI를 만들지 않고 설명용 정적 자료로도 충분하다.

## 이해도 확인

사전에 프로젝트 설명을 듣지 않은 다른 참가자에게 완성된 자료를 제시한다.
5분 안에 무엇을 왜 만들었고 교정이 어떻게 다음 결과에 반영됐는지 설명 가능한지 확인한다.
관측 시간, 자료 버전, 실제 응답 요지, 혼동점, 수정한 설명을 demo-transcript.md에 남긴다.
여력이 있으면 교정 1회 등록 hands-on도 관찰한다. 필수 관찰을 하지 않은 상태에서 통과라고 쓰지 않는다.
이 확인은 설명 이해도이며 서비스 전체 사용성을 검증한 것으로 확대하지 않는다.

## 제출 점검

README, 데모 영상, HTML 또는 PPT, 이해도 기록, make run/verify/범용 seed 또는 승인된 대체,
golden/scenario/transcript를 실제 증거와 대조한다. 최소 설명물은 기능 축소 목록으로 빼지 않는다.
