## 스토리 분해 접근법 (트레이드오프)
- **User Journey-Based**: 사용자 워크플로우(세션 시작→로드→작업→저장/잔소리→다음 세션 전파)를 따라 스토리 구성. 장점: 전파 루프의 end-to-end 흐름과 C0/C1/C2 증명이 자연스러움. 단점: 불변식 단위 커버리지가 흩어질 수 있음.
- **Feature-Based**: 시스템 기능(인덱스 주입, 로드/refs 확장, 잔소리 적용, 임계값/compaction, 보호필드, 실패 격리) 중심. 장점: R-ID/불변식 매핑이 깔끔. 단점: 사용자 서사가 약해질 수 있음.
- **Persona-Based**: 페르소나(교정자/소비자/운영·검증자)별 필요 중심. 장점: 관심사·책임 분리 명확. 단점: 기능이 페르소나 간 중복될 수 있음.
- **Domain-Based**: 비즈니스 도메인(Capsule 버전관리 / 세션·활성범위 / 보안경계 / 검증·증거) 중심.
- **Epic-Based**: 상위 에픽 아래 하위 스토리 계층 구조.
- **Hybrid**: 예) Journey를 큰 에픽으로 두고 그 아래 Feature 단위 스토리 + 불변식 수용 기준. (제품 책임자 권고안)
