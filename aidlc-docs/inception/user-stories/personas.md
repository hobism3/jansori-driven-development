## P1 — 교정자 (The Corrector / "잔소리하는 사용자")

- **원형**: Claude Code로 실제 작업을 수행하다가, 로드된 skill(Capsule)의 지시가 부족하거나 어긋난 지점을 발견하고 자연어로 교정("잔소리")을 남기는 개발자.
- **목표/동기**:
  - 자신이 겪은 문제가 다음 사람에게 반복되지 않도록 교정을 skill에 축적하고 싶다.
  - 기존의 유효한 규칙을 훼손하지 않으면서 새 교정을 더하고 싶다.
  - 최소한의 마찰로(별도 도구 학습 없이) 자연어·`/jansori:save`·`/jansori:nag`로 교정을 남기고 싶다.
- **행동 특성**: 작업 흐름 중간·완료 시점에 교정을 남김. 부모/자식 skill 중 어디를 고치는지 항상 명확히 알지는 못함(→ 시스템이 대상 판정·확인).
- **핵심 관심사(요구사항 연결)**:
  - 교정이 동일 `skill_id`의 새 version으로 안전하게 누적(R-07, I-01/I-03/I-13).
  - 대상(parent/child) 오판 방지, 모호하면 먼저 확인(R-08, I-13).
  - 보호 필드(name·description·keywords·assets·refs)는 명시 승인 없이는 변경되지 않음(R-11, I-14).
  - 과길이 시 기존 내용 보존·거부(자름 없음)(I-09).
- **성공 기준**: 남긴 교정이 유효 지시를 잃지 않고 새 version에 반영되고, 재시도해도 중복 생성되지 않는다(I-05).

## P2 — 다음-세션 소비자 (The Next-Session Consumer)

- **원형**: 새 세션(새 작업)에서 동일 `skill_id` skill을 로드해 실제 작업을 수행하는 개발자. 앞선 교정자의 존재를 알 필요 없이, 최신 확정 내용을 이어받는다.
- **목표/동기**:
  - 세션 시작 시 관련 skill을 쉽게 발견·로드하고, 최신 교정이 반영된 지시로 작업하고 싶다.
  - skill 서버가 느리거나 실패해도 자신의 작업이 막히지 않기를 원한다(fail-open).
- **행동 특성**: "새 작업 = 새 세션". 한 세션은 하나의 parent + 그 직속 children을 활성화(refs depth-1). 인덱스 이름/설명으로 Claude가 선택(훅 내 LLM 호출 없음).
- **핵심 관심사(요구사항 연결)**:
  - 작업 시작 시 인덱스 주입(R-01, I-08)과 선택·로드(R-02).
  - parent 로드 시 refs children의 body+corrections 확장, depth-1 유지(R-03, I-02/I-03/I-15).
  - 로드된 최신 확정 내용이 실제 실행에 반영(R-04, R-14, I-01/I-02/I-03).
  - compaction 중에도 즉시 진행(폴링/대기 없음), 진행 상태 ≠ 콘텐츠(R-10, I-10).
  - 서버 실패가 작업을 막지 않음(R-12, I-07/I-08).
- **성공 기준**: 앞선 교정이 반영된 **실제 코드/행동 변화**를 경험한다(C0→C1→C2 3상태로 증명 가능).

## P3 — 운영·검증자 (The Operator / Verifier — 팀)

- **원형**: Jansori Plugin + 로컬 서버를 설치·실행하고, 기계적 계약(`make verify`)과 실제 전파 증거(transcript)로 시스템을 검증하며, 보안 경계와 증거-정직성을 책임지는 팀 구성원.
- **목표/동기**:
  - `make run`/`make verify`/`make seed`로 재현 가능하게 시스템을 세우고 검증하고 싶다.
  - 샘플 기능 검사와 실제 Plugin 전파 증거를 명확히 구분해 기록하고 싶다.
  - §5 보안 경계(loopback-only, 경로 격리, 스크립트 자동실행 금지, 소스/프롬프트 자동수집 금지)를 강제하고 싶다.
  - 실제로 수행하지 않은 테스트·동의·시연을 완료로 기록하지 않는다(F-04).
- **행동 특성**: 서버를 실제로 기동해 계약을 검사(가짜 Store 통과 ≠ 검증). C0/C1/C2 3상태를 동일 원본 워크로드·동일 요청으로 실행하고 로드된 version을 매 회 기록.
- **핵심 관심사(요구사항 연결)**:
  - §5 보안 전반(R 관련 조건; DEV-24/33/34/35).
  - PBT 속성 검증(PBT-01..10) — 불변식·round-trip·멱등성·stateful·oracle.
  - 증거 정직성/검증 접근(§7/§11 F-04; deliverables 표) — expected+actual 증거, unverified/failed/unimplemented/approved-exclusion 구분.
  - 서버 실패가 중복 등록을 유발하지 않음 검증(R-13, I-06/I-07).
- **성공 기준**: `make verify` 기계적 통과 + 실제 3상태 transcript로 전파가 증명되고, 미수행 항목은 정직하게 미검증/미구현으로 남는다.
